# 작업자 생성 권한 및 관리자 화면 데이터 정리 계획

작성일: 2026-11-02 (Asia/Seoul)

> 후속 수정: 이 문서의 “고정 DTO는 화면에서도 표시할 수 있다”는 기준은 [작업자 생성 버튼 및 관리자 화면 실데이터 표시 개선 계획](admin-worker-create-and-real-data-display-fix-plan.md)으로 대체한다. 고정 DTO API 코드는 보존하고, 관리자 화면에서는 실제 데이터와 빈 상태를 표시한다. 생성 버튼·생성 결과 확인도 후속 계획을 우선 적용한다.

## 1. 목적과 적용 기준

다음 두 요구사항을 현재 Thymeleaf 이전 구현에 반영한다.

1. 작업자 계정 생성은 관리자로 로그인한 상태에서만 허용한다.
2. 관리자 화면에 표시하기 위해 별도로 작성한 더미 데이터는 삭제한다. 단, 비즈니스 로직이 아직 없는 정식 API의 고정 DTO 반환 구현은 유지한다.

이번 산출물은 변경 계획서다. 애플리케이션 코드 수정과 테스트 실행은 구현 단계에서 진행한다. 기존 이전 계획 중 공개 작업자 가입과 화면별 독립 샘플 데이터 사용에 관한 내용은 이 문서를 우선 적용한다.

**해석 기준:** 예외로 지정한 고정 DTO는 화면에서도 표시할 수 있다. 따라서 이번 작업이 완료되어도 미구현 도메인의 고정 DTO에 포함된 예시 값은 표시될 수 있다. 삭제 대상은 그 응답과 별개로 화면·JS·MVC에 작성한 임의 업무 데이터와 가상 상태 변경이다. 모든 화면을 실데이터로 바꾸거나 미구현 API를 빈 응답으로 바꾸는 작업은 포함하지 않는다.

## 3. 작업자 계정 생성 정책

### 3.1 화면과 API 흐름

관리자 로그인 → `/admin/workers` → 기존 작업자 생성 폼 → `POST /api/admin/workers` 순서로 통일한다.

- 기존 입력 계약 `workerName`, `sex`, `age`와 실제 생성 서비스 호출을 유지한다.
- 생성 결과의 작업자 ID와 임시 비밀번호를 기존 방식으로 전달한다. 공개 가입 폼의 이메일·직접 지정 비밀번호 입력은 이 경로에 추가하지 않는다.
- 로그인 화면의 계정 생성 링크와 공개 가입 템플릿, 가입용 JS를 삭제한다.
- `/admin/register`의 공개 허용 설정을 제거한다. 기존 주소로 접근하는 로그인된 관리자는 `/admin/workers`로 리다이렉트하고, 비로그인 사용자는 로그인으로 이동하도록 한다. 별도의 가입 화면은 제공하지 않는다.
- `WorkerController.register`와 `/api/worker/auth/register`의 `permitAll`을 제거한다. 이 API를 관리자용으로 옮기거나 중복 생성 API를 만들지 않는다.
- `WorkerRegisterRequest`, `RegisterResult` 등 공개 가입에서만 쓰던 DTO는 전체 참조를 확인한 뒤 사용처가 사라진 항목만 삭제한다.

### 3.2 서버의 접근 제어

작업자 생성은 버튼 표시뿐 아니라 서버의 `/api/admin/workers` 권한 검사로 통제한다.

| 요청 주체 | 생성 API 결과 | 확인 사항 |
| --- | --- | --- |
| 비로그인 | 인증 실패 401 | 계정·프로필 생성 없음 |
| 작업자 Bearer 토큰만 보유 | 생성 불가 | ADMIN 세션 권한으로 인정하지 않음 |
| 관리자 세션, CSRF 누락·오류 | 403 | 생성 없음 |
| 관리자 세션, 유효한 CSRF·입력 | 201 | 기존 실제 생성 수행 |
| 로그아웃 후 기존 세션으로 요청 | 인증 실패 | 생성 없음 |

`/api/worker/**`는 기존 stateless Bearer 체인에 속한다. 폐기한 공개 가입 경로를 단순히 `hasRole("ADMIN")`으로 바꾸면 관리자 세션 기반 생성 정책과 맞지 않는다. 생성은 이미 올바른 보안 체인에 있는 `/api/admin/workers`에서만 수행한다.

폐기 경로는 더 이상 가입 성공 DTO를 반환하지 않아야 한다. 해당 URL의 최종 HTTP 상태는 보안 필터 적용 여부에 따라 401/403/404가 될 수 있으므로 모든 주체에 일률적인 404를 강제하려고 별도 예외 경로를 만들지 않는다.

## 4. 더미 데이터 삭제와 고정 DTO 예외의 경계

### 4.1 삭제할 것

- 화면 또는 JS에 직접 작성한 가상 작업자·이벤트·관리자·통계·시각·위치·통신 상태.
- 동일 DTO와 다른 값으로 구성한 MVC 전용 중복 상수 및 사용하지 않는 샘플 Model 속성.
- 응답 내용과 무관하게 항상 신규·온라인·성공으로 표시하는 코드.
- 서버 응답 없이 상태를 진행시키거나 목록·통계가 저장된 것처럼 바꾸는 클라이언트 로직.
- 실제 현장 설정이나 기존 DTO에 근거하지 않는 예시 SVG 지도와 건물·제한구역 배치.
- 조회 실패·빈 결과를 감추기 위해 넣는 대체 샘플 행이나 임의 기본 업무 수치.

### 4.2 유지할 것

- 기존 서비스에서 조회한 작업자·이벤트·대시보드의 실제 값.
- `AdminDomainApiController`의 미구현 도메인 조회·변경 API와 고정 DTO 반환, 그리고 그 반환에 필요한 `AdminUiFixtures`의 불변 데이터.
- 예외 DTO의 값을 그대로 표시하기 위한 템플릿 바인딩·배지·시간 형식·정렬 등 표시 처리.
- 제목·메뉴·아이콘·버튼·입력 예시 문구, `-`·`조회 중`·빈 목록·오류 안내 같은 UI 문구.
- 기존 CSS와 반응형 배치. 데이터가 없을 때도 화면 구조는 유지한다.

삭제할 임의 화면 데이터를 새 고정 API로 옮겨 예외 처리하지 않는다. 이미 있는 미구현 API 계약과 응답을 기준으로 판단한다. 공개 가입 경로의 폐기는 1번 요구사항에 따른 별도 변경이므로 고정 DTO 예외보다 우선한다.

### 4.3 Thymeleaf에서 고정 DTO를 공유하는 방법

SSR을 유지하면서 REST 응답과 최초 화면의 데이터 정의를 일치시킨다.

1. `AdminUiFixtures`를 기존 미구현 도메인 응답의 불변 정의 위치로 사용한다.
2. API와 MVC에 중복된 대시보드·구역 상세 DTO 구성은 해당 클래스의 작은 응답 구성 메서드로 모은다. 이 메서드는 기존 상수와 요청 ID로 DTO를 반환하는 역할만 한다.
3. `AdminDomainApiController`와 `AdminWebController`는 같은 응답 정의를 소비한다. MVC가 REST 컨트롤러를 주입받거나 자체 서버로 HTTP 요청을 보내지 않는다.
4. 한 곳에서만 사용하는 고정 반환은 현재 API 메서드에 둔다. 조회 서비스·저장소·provider 계층은 추가하지 않는다.
5. 고정 응답의 업무 미구현·무저장·미전송 범위와 실제 서비스로 교체할 위치를 TODO로 남긴다.

현재 API의 수치가 서로 맞지 않는 부분이 있더라도 이번 정리에서 새 집계 로직을 만들지 않는다. 중복된 화면 전용 값을 제거하여 하나의 응답 정의를 사용하고, 응답 내용 자체의 변경이 필요하면 별도 확인 항목으로 기록한다.

## 5. 화면별 적용 계획

| 화면 | 데이터 처리 및 제거 사항 |
| --- | --- |
| 로그인 | 공개 생성 링크 삭제. 실제 관리자 로그인 유지 |
| 작업자 목록·상세 | 작업자 신원·계정·이벤트는 기존 실데이터 사용. 상태·생체신호·NFC 등은 기존 고정 DTO 응답 표시. 응답의 샘플 이름으로 실제 작업자 이름을 덮어쓰지 않음 |
| 대시보드 | 작업자 수·미처리 수·최근 실제 이벤트는 기존 `SafetyService.dashboard()` 사용. 미구현 상태·구역 등은 기존 고정 DTO 필드 사용. 같은 지표를 별도 화면 상수로 구성하지 않음 |
| 이벤트 이력 | 기존 실제 목록·상세·처리 API 유지. 사용하지 않는 샘플 Model 삭제 |
| 긴급 알림·대응 | 기존 고정 대시보드 DTO의 이벤트·상태 사용. JS 샘플 매핑과 무조건 온라인 표시 삭제 |
| 구역·상세 | 기존 구역·작업자·제한구역 고정 DTO 사용. 임의 SVG 지도 제거 후 같은 영역에 지도 미등록 상태 표시 |
| 기기·통신 | 기존 상태 DTO 사용. 별도 가상 이벤트 목록으로 미해결 여부를 판정하지 않음. DTO로 확인할 수 없으면 `-` 표시 |
| 날씨 | 기존 날씨·공지 DTO 유지. 템플릿/JS에 별도 측정값·시각을 두지 않음 |
| 처리 기록·보고서 | 기존 감사 DTO 유지. 실제 전체 이벤트 수는 기존 실제 대시보드 값 사용. DTO에 없는 전체 해결 건수는 추측해 표시하지 않음 |
| 설정·관리자 | 기존 고정 DTO와 변경 API 유지. 응답 없이 화면에서 저장 완료·권한 변경을 확정하지 않음 |

실제 집계와 고정 DTO 통계가 서로 다른 범위를 나타내면 한 지표로 합산하지 않는다. 실제 값이 존재하는 동일 지표는 기존 서비스 값을 우선하고, 정의가 없는 지표는 `-`로 표시한다. 페이지 일부의 행 개수를 전체 통계로 표시하지 않는다.

### 5.1 상세 링크와 이벤트 모달

- 실제 이벤트는 기존 `/admin/events/{eventId}/detail`과 `/api/admin/events/{eventId}/process`를 사용한다.
- 고정 DTO 이벤트는 해당 응답으로 렌더링한 Thymeleaf 상세 템플릿을 모달에 표시한다. ID별 JS 상수 사전이나 별도 가상 이벤트 저장소를 두지 않는다.
- 기존 고정 응답 acknowledge/resolve API는 경로와 DTO를 유지한다. 버튼 응답은 반환된 상태로 표시하며 최초 상태를 임의로 신규로 설정하지 않는다. 재조회 시 고정 값이 돌아오는 기존 정책을 유지한다.
- 고정 DTO의 작업자 ID가 실제 DB 작업자임을 가정하지 않는다. 실제 목록에서 확인되지 않은 샘플 작업자를 실제 상세·초기화·생성 후속 동작의 대상으로 연결하지 않는다. DB 조회 실패를 샘플 상세 화면으로 대체하지 않는다.

DB 스키마, Entity, 기존 실제 비즈니스 로직과 새 도메인의 저장·전송·판정 로직은 이번 변경 범위에 포함하지 않는다.

## 7. 실행 순서와 검증

1. 공개 생성 경로와 참조를 정리한다. → 로그인 전 링크가 없고, 실제 생성이 ADMIN 세션·CSRF를 요구하는지 검증한다.
2. 화면별 데이터 출처를 정리한다. → 실데이터, 기존 고정 DTO, UI 정적 문구 중 어디에 속하는지 확인하고 독립 업무 샘플을 삭제한다.
3. 중복 DTO 구성을 공통화하고 Thymeleaf 바인딩·모달을 수정한다. → 같은 응답을 API와 화면이 사용하고 별도 샘플 매핑이 없는지 검증한다.
4. 빈 결과·조회 실패·샘플 ID 링크를 정리한다. → 실제 객체가 없을 때 가짜 행·성공·상세 화면을 만들지 않는지 검증한다.
5. 회귀 테스트와 화면 확인 후 문서를 갱신한다. → 빌드와 아래 완료 조건을 확인한다.

### 7.1 자동 검증 항목

- 관리자 생성 권한 표의 각 경우에 계정·프로필 증가 여부를 함께 확인한다.
- 관리자 세션과 유효한 CSRF로 실제 작업자를 생성하고, 목록·상세·임시 비밀번호 로그인까지 기존 동작을 검증한다.
- 폐기한 공개 가입 URL은 익명·작업자·관리자 요청 모두 가입 성공 DTO를 반환하거나 계정을 생성하지 않는지 확인한다.
- 로그인 화면에 공개 생성 링크가 없고, 기존 가입 화면 주소는 비로그인 시 로그인·관리자 로그인 시 작업자 관리로 이동하는지 확인한다.
- 실제 목록이 비어 있거나 조회가 실패하면 샘플 작업자·이벤트를 삽입하지 않는지 확인한다.
- 실제 DTO와 예외 고정 DTO의 필드가 각각 올바르게 렌더링되고, 사용하지 않는 Model 속성과 JS ID별 샘플 사전이 제거되었는지 확인한다.
- 미구현 API 경로·응답 계약이 유지되고, 호출 후 DB나 실제 권한이 변경되지 않는지 기존 검증을 유지한다.
- 화면에 `김민준`·`1001` 등이 있다는 사실만으로 실패 처리하지 않는다. 그 값이 허용한 고정 DTO에서 왔는지 확인한다.
- 기존 Bearer 인증·관리자 CSRF·이벤트 처리·비밀번호 초기화 테스트를 포함해 `.\mvnw.cmd clean verify`를 실행한다.

### 7.2 브라우저 확인 항목

- 비로그인 화면에서 생성 진입점이 사라지고, 관리자 로그인 후 작업자 생성이 가능한지 확인한다.
- 임의 지도 제거 후 안내·빈 영역과 반응형 배치가 유지되는지 확인한다.
- 이벤트 모달의 이름·유형·초기 상태가 표시된 DTO와 일치하는지 확인한다.
- 빈 목록, 통신 오류, 세션 만료 시 임의 값이나 기존 샘플로 대체하지 않는지 확인한다.
- 고정 DTO의 작업자 링크가 실제 DB에 없는 작업자로 연결되지 않는지 확인한다.

## 8. 완료 조건

- 작업자 계정 생성이 관리자 로그인 상태에서 기존 정식 생성 API로만 가능하다.
- 공개 가입 화면·성공 응답 API·호출 코드가 제거되어 있다.
- 화면에 직접 작성한 가상 업무 데이터와 예시 지도가 제거되어 있다.
- 미구현 도메인의 기존 고정 DTO 반환은 정식 경로·계약·TODO와 함께 유지된다.
- 같은 응답에 대한 별도 JS 샘플 사전이나 MVC 중복 업무 값이 없다.
- 실제 데이터와 고정 DTO의 표시·객체 참조가 섞이지 않으며, 없는 데이터는 빈 상태 또는 `-`로 표시한다.
- 회귀 테스트와 브라우저 확인 결과를 구현 완료 보고에 기록한다.
